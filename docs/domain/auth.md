# 인증 (사용자·로그인 세션)

사용자가 누구인지 구분하고 로그인 상태를 유지하는 규칙이다. 방 안에서 참여자를 다루는 규칙은 `pomodoro.md` 에 있다.

## 게스트

- 사용자는 로그인하지 않아도 자동으로 게스트로 로그인된다. 로그인 화면은 없다.
- 로그아웃은 없다.
- 게스트는 브라우저로 구분한다. 같은 브라우저의 탭들은 같은 게스트다. 탭을 여러 개 열 수 있다.
- 게스트는 참여자 ID 하나로 구분한다. 게스트가 하는 일은 방 참여뿐이라 따로 사용자 ID 를 두지 않는다.
- 브라우저 데이터를 지우거나 시크릿 창으로 들어오면 새 참여자 ID 를 받는 새 게스트가 된다. 이전 게스트는 되찾을 수 없다.
- 게스트에는 방 밖에 남는 정보가 없다. 닉네임과 상태 메시지는 방 안에서만 있다.

## 참여자 ID

- 참여자 ID 는 방에서 사람을 구별하는 값이다. 브라우저마다 하나이고, 어느 방에 들어가도 같다.
- 닉네임과 상태 메시지는 참여자 ID 가 아니라 방에 딸린다.

## 로그인 유지

- 게스트 정보는 서버 세션에 둔다. 참여자 ID 는 서버가 만들어 세션에 담는다.

> **현재 구현과 다름**
> 지금은 서버 세션 없이 참여자 ID 를 담은 서명 JWT 를 HttpOnly 쿠키로 준다. `.claude/rules/backend.md` 4.3 과 `apps/api/docs/api.md` 가 이 구현을 설명하므로, 서버 세션으로 바꿀 때 함께 고친다.

## 구글 로그인 (추후)

- 구글 로그인 사용자는 회원 ID(userId)를 따로 가진다. 로그인하면 세션에 회원 ID 를 더한다. 통계처럼 방 밖에 남아야 하는 정보는 회원 ID 에 묶는다.
- 로그인해도 세션의 참여자 ID 는 바뀌지 않는다. 방에 참여 중이었다면 그대로 참여 중이다.
- 구글 로그인 사용자도 방에서는 참여자 ID 로 구분한다.

## 논의 필요

아직 팀과 합의하지 않은 규칙이다. 지금 구현은 그대로 두고, 이 규칙을 바꾸거나 새로 기대는 작업은 먼저 확인받는다.

### 같은 구글 계정으로 여러 브라우저에서 들어오기

- 쟁점: 같은 구글 계정으로 여러 기기·브라우저에서 들어오면 참여자 ID 가 여럿이 된다. "한 번에 한 방" 규칙(`pomodoro.md`)을 계정 단위로 지킬지, 계정이 이미 다른 방에 있으면 어떻게 할지 정해야 한다. 구글 로그인을 설계할 때 정한다.

### 구글 로그인 사용자의 닉네임

- 이전 문서: 방마다 그 방의 닉네임을 받고, 구글 계정 이름을 닉네임으로 쓰지 않는다.
- 쟁점: 닉네임 규칙 전체(`pomodoro.md` 의 닉네임)가 논의 중이라 함께 정한다.

### 따로 묻지 않고 확정에 둔 항목

- 게스트에는 방 밖에 남는 정보가 없음, 참여자 ID 는 브라우저마다 하나, 구글 로그인 사용자도 방에서는 참여자 ID 로 구분. 기존대로 확정에 두었으니 다르면 알려 준다.
