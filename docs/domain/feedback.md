# 피드백(feedback) 도메인

사용자가 서비스 안에서 운영자에게 피드백을 보내는 규칙을 정리한다. 구현 방법이 아니라 **무엇이 참이어야 하는지**를 적는다.

## 용어

| 용어   | 뜻                                                                   |
| ------ | -------------------------------------------------------------------- |
| 피드백 | 사용자가 운영자에게 보내는 내용과 첨부. 운영 메일로 한 통씩 도착한다 |
| 첨부   | 피드백에 붙이는 사진·동영상 파일                                     |

## 보내기

- 피드백은 방 화면에서 보낸다.
- 메일 주소는 받지 않는다. 그래서 운영자가 답장할 수 없다.
- 내용은 필수다. 앞뒤 공백을 빼고 비어 있으면 보낼 수 없다. 첨부만 있는 피드백도 보낼 수 없다.
- 내용은 최대 60,000자다(`FEEDBACK_CONTENT_MAX_LENGTH`). 글자 수는 화면과 서버가 같은 방식(`string.length`)으로 센다. 첨부를 최대로 채워도 메일 한 통 한도(25MB) 안에 들어가는 길이다.
- 메일 발송에 실패하면 실패로 알리고, 입력한 내용과 첨부는 그대로 남아 다시 보낼 수 있다.

## 첨부

- 첨부는 선택이다.
- 첨부는 합계 18,000,000바이트, 최대 500개까지 붙일 수 있다(`FEEDBACK_ATTACHMENT_MAX_TOTAL_BYTES`, `FEEDBACK_ATTACHMENT_MAX_COUNT`). Gmail 메일 한 통 25MB(첨부는 base64로 약 1.37배 커진다)와 메일 한 통에 받을 수 있는 첨부 500개 한도에서 정했다.
- 첨부는 파일 내용으로 판별한 PNG·JPEG·GIF·WebP·MP4·MOV·WebM만 받는다. SVG처럼 내용으로 판별할 수 없는 형식은 받지 않는다.
- 확장자와 내용이 달라도 내용을 따른다. 메일에 붙는 첨부의 형식과 확장자는 판별한 형식으로 정한다.
- 메일의 첨부 이름은 사용자 파일 이름에서 보이지 않는 문자와 경로 문자를 지우고, 원래 확장자 대신 판별한 확장자를 붙인 것이다. 이름으로 형식을 위장하지 못하게 하기 위해서다.
- 확장자를 뺀 첨부 이름은 250바이트까지다. 운영자가 내려받을 때 OS의 파일 이름 한도(255바이트)를 넘지 않게 하기 위해서다. 정리한 뒤 이름이 비면 `attachment-<순번>`으로 한다.
- 화면은 파일 확장자만 보고 미리 안내한다. 최종 판정은 서버가 내용으로 한다.
- 첨부는 서버에 보관하지 않는다. 발송하는 동안만 임시로 두고, 발송이 끝나면 성공·실패와 관계없이 지운다.

## 메일

- 피드백은 운영 Gmail 계정이 자기 자신에게 보내는 메일로 도착한다.
- 메일 제목은 고정이다. 사용자 입력은 제목에 넣지 않는다.
- 메일 본문에는 내용과 함께 접수 시각(KST), IP, 참여자 ID, 브라우저 정보가 들어간다. 본문만 보고 바로 로그를 찾기 위해서다.

## 접수 한도

- 하루(KST 00:00 기준)에 전체 100건, 첨부 합계 500,000,000바이트까지 받는다. 한도를 넘으면 그날은 더 접수하지 않는다.
  - 100건: Gmail 개인 계정의 하루 발송 한도(약 500통)에 여유를 둔 값이다.
  - 500,000,000바이트: Gmail 저장 공간 15GB가 가득 차는 데 30일이 걸리는 양이다. 공격이 이어져도 운영자가 알아챌 시간을 둔다.
- 건수와 용량은 발송 성공 여부와 관계없이 발송을 시도한 피드백으로 센다.
- 사람(IP·참여자 ID)별 제한은 아직 없다. 근거가 될 데이터가 없어서, 제출 기록을 보고 정한다.

- 피드백 저장·조회, 관리자 페이지
